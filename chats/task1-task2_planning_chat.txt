  Task 2: Near-duplicate detection (Colab, NumPy only, under 15 minutes)

  Method: MinHash plus LSH banding, then an exact Jaccard check on every 
  candidate pair. This gives the "probability a pair is examined" plot the
  handbook asks for. The exact check means you report no false pairs.

  1. Shingles: split with t.split() and build 5-word sequences. A document with
     fewer than 5 words gets exactly one shingle: its whole word list. Hash each
     shingle to a 64-bit integer and store each document as a sorted,
     de-duplicated NumPy array. Keep case and punctuation exactly as they are.
  2. MinHash signatures: use k = 100 hash functions of the form (a*x + b) mod p,
     vectorised per document, giving one row of minimums per document.
  3. LSH banding: use b = 20 bands of r = 5 rows. The chance a pair is examined
     is 1 − (1 − J⁵)²⁰, which is about 0.9997 at J = 0.8 and about 0.5 at J =
     0.5. Hash each band and group documents into buckets; pairs within a bucket
     become candidates.
  4. Size filter: if J ≥ 0.8, the smaller shingle set must be at least 0.8 × the
     larger one. This removes many candidates cheaply.
  5. Exact check: compute the true Jaccard with np.intersect1d, keep pairs with
     J ≥ 0.8, and order each pair so id1 < id2.

  Traps to handle:
  - Shared boilerplate makes huge buckets. Cap the bucket size or handle large
    buckets separately, and measure the effect.
  - Groups of three identical documents must produce all 3 pairs.
  - Very short documents are covered by the single-shingle rule above.

  Deliverables:
  - submission.csv with columns id1,id2.
  - Dev results: precision, recall and F1, plus 3 missed and 3 wrong pairs with

  - Scaling test at n = 5k, 10k, 20k, 40k and 80k, with a log-log plot and the

  Task 3: Association rule mining (exact match required)

  The data is easy for this kind of task: about 2,000 items, baskets of about 11
  items on average, and itemsets up to size 9.

  Method: Eclat-style search using bitsets. Each item gets a 500,000-bit vector
  (about 62 KB). The count of an itemset is popcount(AND of its item vectors).

  1. Read the transactions and count single items. Use min_count = 
     ceil(3*n/1000) in integer arithmetic to avoid float errors.
  2. Keep the frequent single items and build one bit vector per item with
     np.packbits.
  3. Search depth-first. Extend an itemset only with larger item ids so nothing
     is generated twice. Intersect bitsets, count with np.bitwise_count (or a
     lookup table), and prune anything below min_count. Record how many
     candidates were examined and how many were frequent at each size, because
     the handbook asks for that table.
  4. Rules: for each frequent itemset I, try every non-empty proper subset A as
     the antecedent. Every subset of a frequent itemset is frequent, so its
     count is already known. Test confidence with integers, 5*count(I) >= 
     3*count(A), to avoid float problems at exactly 0.6.
  5. Output: items sorted ascending and joined with spaces; confidence written
     as f"{c:.6f}". Check the exact rounding against dev_rules.csv.
  6. Check against the dev keys: count missing, extra and wrong entries for
     itemsets, counts, rules and confidences. The goal is all zeros.
  7. Scaling: run 4 sizes (62.5k, 125k, 250k, 500k) and 3 or more support levels
     (0.002, 0.003, 0.004, 0.005), with plots and the complexity of each stage.

  The problem: you have 112,571 text documents, mostly Wikipedia articles. Some

  1. Shingles: split the text on spaces and take every run of 5 consecutive

  ---

  Part 1: The problem

  Input: 112,571 documents, each with an id and a text.
  Output: every pair of documents whose Jaccard similarity is ≥ 0.8.

  What "similar" means here

  1. Shingling. A document is turned into a set of 5-word phrases (word
     5-grams).
     - "the cat sat on the mat" gives {"the cat sat on the", "cat sat on the 
       mat"}.
     - A document with fewer than 5 words has one shingle: its whole text.
     - Case and punctuation are kept as written, so "The" and "the" are
       different words.
  2. Jaccard similarity.
     - J(A,B) = |A ∩ B| / |A ∪ B|, that is, shared shingles divided by all
       distinct shingles.
     - Example: A has 100 shingles and B has 100 shingles; they share 90.
     - J = 90 / (100 + 100 − 90) = 90 / 110 = 0.818, so this pair is a
       near-duplicate.

  Why it's hard

  - Too many pairs to check. Comparing every pair means n(n−1)/2 ≈ 6.3 billion
    comparisons. Each one is a set intersection of about 600 shingles. My
    measurement puts this at about 67 hours, and the limit is 15 minutes.
  - Libraries are restricted. Only NumPy, SciPy, pandas and matplotlib are
    allowed; no datasketch, faiss or sklearn.
  - The data contains deliberate traps: shared boilerplate, pairs just below
    0.8, triple duplicates and very short documents.

  ---

  Part 2: The solution

  There is no ML model

  This is not machine learning. Nothing is trained and no neural network is
  involved. It is a randomised hashing algorithm called MinHash with 
  Locality-Sensitive Hashing (LSH), followed by an exact check. In the viva,
  call it an algorithm or method, not a model.

  The core idea

  Brute force asks, for every pair, "how similar are they?" That is O(n²).

  LSH turns this around: give each document a few short fingerprints, chosen so
  that similar documents very probably share a fingerprint and dissimilar ones
  almost never do. Then you only compare documents that share a fingerprint.
  That is roughly O(n).

  Pipeline (4 stages)

  texts ──► [1] Shingling ──► [2] MinHash ──► [3] LSH banding ──► [4] Exact 
  verify ──► pairs
            words → 64-bit     100 numbers     20 bands × 5 rows    true Jaccard
  ≥ 0.8
            hashes per doc     per doc         → candidate pairs

  Stage 1: Shingling and hashing.
  - Each 5-word shingle becomes one 64-bit integer.
  - Integers are much faster to compare than strings and use less memory.
  - Each document becomes a sorted, unique NumPy array of these integers, which
    is its shingle set.

  Stage 2: MinHash. This is the key mathematical fact.
  - Take a random hash function h and apply it to every shingle of a document.
    Keep the minimum value.
  - For two documents A and B: P[min h(A) = min h(B)] = J(A,B).
  - Why: consider all shingles in A ∪ B. The one with the smallest hash is
    equally likely to be any of them. The two minimums are equal only if that
    smallest shingle lies in A ∩ B. The probability of that is |A∩B| / |A∪B| =
    J.
  - With 100 different hash functions, each document gets a signature of 100
    numbers. The fraction of positions where two signatures agree estimates J.
  - Each document is now 100 numbers instead of hundreds or thousands of
    shingles.

  Stage 3: LSH banding.
  - Split the 100 numbers into b = 20 bands of r = 5 numbers each.
  - Within each band, documents whose 5 numbers are all identical go into the
    same bucket. Any two documents in the same bucket become a candidate pair.
  - For a pair with similarity J:
    - P(one band matches fully) = J⁵
    - P(no band matches) = (1 − J⁵)²⁰
    - P(examined) = 1 − (1 − J⁵)²⁰. This is the S-curve.

  ┌───────┬─────────────┬───────────────────────────────────────────────────┐
  │ True  │ P(examined) │                      Meaning                      │
  │   J   │             │                                                   │
  ├───────┼─────────────┼───────────────────────────────────────────────────┤
  │ 0.3   │ 0.047       │ unrelated pairs are almost never checked          │
  ├───────┼─────────────┼───────────────────────────────────────────────────┤
  │ 0.5   │ 0.47        │                                                   │
  ├───────┼─────────────┼───────────────────────────────────────────────────┤
  │ 0.7   │ 0.975       │                                                   │
  ├───────┼─────────────┼───────────────────────────────────────────────────┤
  │ 0.8   │ 0.9996      │ true pairs are almost never missed (a 0.04% miss  │
  │       │             │ chance)                                           │
  └───────┴─────────────┴───────────────────────────────────────────────────┘

  - The steep part of the curve sits at about (1/b)^(1/r) = (1/20)^(1/5) ≈ 0.55.
    That is safely below 0.8, which favours recall.

  Stage 4: Exact verification.
  - Size filter. For every candidate pair, check min(|A|,|B|) / max(|A|,|B|). If
    that ratio is below 0.8, skip the pair: J can never exceed that ratio,
    because the intersection is at most the smaller set and the union is at
    least the larger set.
  - Exact Jaccard. For the rest, compute the true Jaccard on the shingle arrays
    and keep pairs with J ≥ 0.8.
  - Why precision is perfect. Stage 4 means no false pairs are reported; recall
    is the only thing that depends on probability.

  How each trap is handled

  Trap: Shared boilerplate
  How it's handled: Unrelated articles sharing a header have J ≈ 0.2–0.4, so
    P(examined) is only about 1–10%. The few that slip through are rejected
    exactly. The largest bucket on the full corpus held only 68 documents, so
    there is no blow-up.
  ────────────────────────────────────────
  Trap: Pairs just below 0.8
  How it's handled: They do become candidates, but the exact check rejects them.

    The dev run showed 0.7992 and 0.7990 rejected.
  ────────────────────────────────────────
  Trap: Triple duplicates
  How it's handled: All three land in the same bucket, so all 3 pairs are
    generated.
  ────────────────────────────────────────
  Trap: Short documents
  How it's handled: Special case: one shingle for the whole word sequence, so
    identical short texts match and different ones don't.
  ────────────────────────────────────────
  Trap: Hash collisions
  How it's handled: 64-bit hashes give a collision chance of about 2⁻⁶⁴ per
  pair,
    which is negligible.

  Technology used

  - Python + NumPy: almost all the heavy work is vectorised NumPy over arrays of
    about 75 million integers, with no Python loop per shingle.
  - pandas: reading the CSV files and writing submission.csv.
  - matplotlib: the S-curve and log-log plots.
  - Python's dict: mapping each word to an integer id.
  - No forbidden libraries.
